# 密码账本
在桌面管理端维护账本，用离线网页查看条目密码或下载账本副本。条目可以在账本之间复制，复制来的条目仍用原管理密码解密。

## 桌面管理端
在项目根目录运行：
```powershell
python main.py
```
需要 64 位 Python 3.10 或更高版本，带 Tkinter。项目自带 Windows x64 的 DLL 和 Linux x64/glibc 的 SO，不需要安装第三方 Python 包。

1. 新建或打开账本，在顶部输入管理密码，点击“解锁账本”。有条目时默认选中第一条，空账本可直接填写第一条。
2. 填写资料和密码生成规则。解锁后点“生成密码并保存”，会生成新密码和随机码，立即加密并更新条目。手动修改密码或随机码后，点击绿色“保存条目”应用修改。
3. “条目加密设置”可以选择算法、内存（KiB）和迭代次数。改完点“保存条目”应用。只改加密设置时，可以让密码框保持为空，程序会把原来的条目密码用新设置重新加密。
4. 解锁后点“解密密码”查看所选条目的密码。要修改管理密码，点击“更换管理密码”。
5. 点击“保存账本”把修改写入文件。也可以打开“编辑账本文本”，全选并复制给网页查看。
6. 点击“锁定账本”或按 Esc 清空当前管理密码和明文；切换账本、整本导入或退出也会清空。

新建、打开另一份账本或退出前，会提示处理未保存的账本修改。未编辑的空白草稿可以直接离开。取消切换或保存失败时，当前表单和未加密的密码仍保留。

点击“更换管理密码”，输入原管理密码，再输入并确认新管理密码。每条原有的密码会用新的管理密码重新加密，条目里的密码保持原样。全部成功后点击“保存账本”写入文件。只要有一条无法用原管理密码解开，整本就保持原样。

随机码输入框会带出条目当前保存的值。密码和随机码旁用红色标记未保存的输入，用绿色标记已保存的值。手填随机码须为 32 位十六进制。清空随机码后保存会生成新值。对已有密文只改随机码时，可以直接保存条目，原网站密码会保留。每次加密都会独立生成新 nonce。历史账本中已有的空密码仍可读取。

管理端默认显示密码明文。密码框和随机码框各自支持 Ctrl+Z 撤销和 Ctrl+R 重做，保存条目后仍可撤销输入，重新保存才会改变密文。历史只在当前条目的内存中保留，无条数上限。锁定账本或切换条目时会清除历史。

“保存条目”会加密密码并更新当前条目。“保存账本”会把整本账本写入文件。

空账本启用密码时不进行加密运算。已有密文时优先核对选中的条目，选中草稿时核对首条密文。解锁过程不显示网站密码。切换条目清空上条网站密码，保留本次会话的管理密码。

管理密码只保留在当前程序内存，不写入账本或配置。不缓存派生密钥；锁定界面不代表能可靠擦除语言运行时的所有内存副本。

## 离线网页
用浏览器打开项目根目录的 `password_viewer.html`，无需服务器和联网。
1. 点击“打开账本文件”，或者粘贴账本文本后点击“读取粘贴内容”。
2. 输入管理密码，选中条目，点击“解密密码”。首次解密成功后，网页会保留管理密码，供查看其他条目时使用。
3. 解密后默认隐藏条目密码。勾选“显示密码”查看，或直接点击“复制密码”。要换用其他管理密码，先点击“锁定账本”。
4. 点击“下载账本副本”下载 `账本.txt`。下载内容保留账本密文和公开资料，原文件保持原样。

条目维护在 PC 端完成。网页按需解密所选条目，管理密码和解密结果仅用于当前会话。携带一个 `password_viewer.html` 和账本文本即可。HTML 已嵌入 JS、Wasm 及相关许可通知。

两端都有虚构的 `example.vault`。演示管理密码是 `演示管理密码-2026!`，百度条目的密码是 `123456_qwerty`。

## 账本与旧文件
账本是 UTF-8 文本，支持中文和多行备注。服务资料和备注公开可读，密码加密保存。

每个 `[条目]` 都公开记录 `加密算法`、`内存KiB`、`迭代次数` 和 `并行通道`。条目可以使用不同设置。编辑已有条目时，桌面会带出原来保存的设置。新条目默认使用 65536 KiB（64 MiB）和 3 轮。

桌面端和网页都可以读取原有格式 1。短暂使用过的格式 2 也可以打开，桌面下次保存时会把参数写回各条目，保留原密文和随机码。

桌面端的“编辑账本文本”有两个操作。

- “保存当前文本”把编辑框里通过校验的整份文本写入账本文件。首次保存时会询问文件位置。
- “粘贴并追加…”打开空白窗口。粘贴一条或多条完整的 `[条目]`，或者粘贴整份来源账本，再点击“追加到当前账本”。当前账本末尾会出现新条目。点击“保存当前文本”写入文件。手动编辑过账本文本时，请先保存这些修改，再追加。

也可以直接用文本编辑器打开目标 `.vault` 或 `.txt`，在末尾另起一行粘贴完整的 `[条目]` 段并以 UTF-8 保存。手写草稿时，把“随机码”和“密码密文”同时留空。

追加会保留原密文、随机码和加密设置。目标账本中其他条目的设置可以不同，复制来的密文仍用原管理密码解密。若来源是临时格式 2，请粘贴包含账本头的全文，以便一同读入共享参数。

重复粘贴同一条会新增一条相同的记录。空账本首次追加已加密的条目后，请用对应的管理密码解锁。

每条密文在解密时独立验证密码。错密码和被篡改的密文都会导致认证失败。跨账本复制的密文需要用更新后的桌面端或网页查看器读取。

    libargon2id.so            Linux x64/glibc 编译产物
    argon2id_native.py        ctypes 调用 C 核心

    text_decoder.py          文本与参数互转

  gui/                       PC 窗口和账本会话

    page.template.html       网页模板

## 加密流程
每条独立采用 Argon2id v1.3（默认 64 MiB、3 轮、4 通道）从管理密码和随机盐派生 32 字节密钥，再由 XChaCha20-Poly1305、ChaCha20-Poly1305 或 AES-256-GCM 加密。GUI 默认选择 XChaCha20-Poly1305。

每次加密生成独立 nonce。“随机码”是 16 字节盐，保存条目使用当前输入，留空时随机生成。密文为 `Base64(nonce || ciphertext || 16 字节认证标签)`，加密载荷为 `16 字节账本码 || 2 字节大端 UTF-8 密码长度 || UTF-8 密码`。

解密按各条目原来记录的参数计算。修改 `config.py` 中的内存和迭代次数默认值会影响之后新建的条目。保存较高设置前桌面会提示，网页还受 128 MiB 的运行上限与浏览器可用内存限制。文件头和密文载荷保留账本码。密文认证通过后跳过载荷里的账本码，继续检查密码长度和 UTF-8 编码。公开资料可编辑。密码保留原始空白和 Unicode 字符。

PC 首次密码计算才加载本地动态库；单次计算沿用一个工作线程，完成后释放。网页首次点击解密才实例化 Wasm。打开账本、搜索和选中条目均不运行 Argon2。实现未经过完整安全审计，也不承诺恒定时间。

## 开发与验证
从项目根目录执行：
```powershell
python -S -X utf8 -B -m unittest discover -s test -v
python -S -X utf8 -B web/build.py
node web/test/test_ciphers.cjs
node web/test/test_text.cjs
node web/test/test_handoff.cjs
node web/test/test_gui_session.cjs
```
Node 只用于开发测试，使用网页不需要它。GUI 单测需要可用的 Tk 环境；网页会话测试使用 DOM 替身，不代表浏览器布局或手机实测。测试中的低成本 Argon2 参数仅用于验证流程，正式默认参数仍为 64 MiB。本轮验证结果见 `test/RESULTS.txt`。

在 `core/` 中重编译本地库：
```sh
# Windows x64，使用对应的 GCC
gcc -std=c99 -O3 -shared -static-libgcc -s argon2id.c -o argon2id.dll
# Linux x64
gcc -std=c99 -O3 -shared -fPIC -fvisibility=hidden -s argon2id.c -o libargon2id.so
```
Wasm 的工具版本、编译命令和源码摘要见 `web/core/BUILD.txt`。修改网页模板或 JS 后运行 `web/build.py`，重新打开生成的 HTML 才会使用新代码。其他 CPU 架构需编译对应的本地库；网页直接使用现有 Wasm。
